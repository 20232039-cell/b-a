# 수집 순서 — 매장 들이기부터 앱까지

정본은 코드다. 이 문서는 흩어진 차례를 한 장에 모은 지도이고, 칸마다 그 결정이 적힌 파일을 적는다.
차례를 바꾸면 여기와 그 파일을 같이 고친다.

## 1. 매장 들이기

1. **씨앗** — 데이터 저장소 `data/brands_seed.csv` 한 줄(slug · 성별 · 공식몰 주소). 사람이 성별을 판정하고,
   목록에서 뺀 매장은 씨앗에서 지운다. 공식몰 주소는 **원화를 파는 한국몰**이어야 한다(해외몰은 달러라
   build-csv 가 통째로 뺀다 — egnarts 2026-09-27).
2. **틀 가르기** — `scripts/platforms.py`
   - 카페24: 기본(`crawl_cafe24.py`).
   - Shopify(`SHOPIFY`) · 식스샵(`SIXSHOP`): 틀 전용 수집기.
   - 그 밖(`PAGES` — 고도몰·위사·메이크샵·직접 만든 사이트): 매장별 해석기 `scripts/stores/<slug>.py` 와
     구동부 `crawl_pages.py`. 해석기 규약은 `crawl_pages.py` 머리말. 시험은 `stores/_try.py`.
   - 편집숍은 **자체 상품만** 걷는다(사람 결정 2026-09-28 — khakis · insane-garage).
3. **첫 수집** — 워크플로 `crawl-brand`(`crawl.yml`, 손으로). 새 매장은 `platforms.NEW_HOLD` 에 넣어
   **사람이 보기 전까지 앱에 안 나가게** 한다.

## 2. 상품 한 벌에서 정보를 얻는 차례

**사이즈표** — 사람이 정한 차례(2026-09-18, `size_from_ocr.py` 합치기 부분). 앞에서 얻으면 뒤는 안 본다.

| 차례 | 어디서 | 누가 거두나 |
|---|---|---|
| ① | 상품 페이지 **서버 HTML** 의 표·글 | `crawl_cafe24.parse_detail` (표 → 글 꼴) |
| ② | **토글·아코디언을 펼친** HTML — 글은 이미 HTML 안에 있다 | 같은 곳(`.accordion-*` · `#prdInfo` 등 그릇 목록) |
| ②' | 자바스크립트가 그리는 표 | `browser_collect.py`(`browser.yml`) |
| ③ | **버튼이 여는 창** — 카페24 사이즈가이드(`/product/sizeguide.html`) · 크리마 핏 위젯 | `fetch_sizeguide.py`(`sizeguide.yml`, 매일) · `fetch_cremafit.py` |
| ④ | 그래도 없으면 **사진** — 상세 그림·사이즈가이드 그림 OCR(tesseract) | `ocr_detail_images.py`(`ocr.yml`) |
| ⑤ | 사람이 옮겨 적은 값 | `data/manual_sizes.csv` — 무엇보다 앞선다 |
| ⑥ | 색만 다른 형제의 표 물려받기 | `size_from_ocr.py` (출처 `sibling`) |

**수집 단계에서 거르는 남의 표**(2026-10-27 사이즈 판독 816벌에서 드러난 것 — `crawl_cafe24` 「사이즈 출처 손질」 칸):
표 칸이 품목과 어긋나면(바지에 상의 칸만 · 스커트에 어깨/소매 · 상의에 허벅지/밑위만) `size_table` 을 비우고
`size_reject` 에 표와 까닭을 남긴다(지난 판 표도 되살리지 않는다). 한 표가 매장의 상관없는 옷 열 벌 넘게 · 품목 셋 넘게
똑같으면 매장 틀로 본다. 상세 그림 주소가 다른 옷(「…SLACKS…」 그림이 재킷에)이나 다른 품번을 가리키면
`detail_images` 에서 빼 `detail_images_foreign` 에 둔다. 사이즈가이드 창은 상품별 칸(`.userGuide`)만 읽고 카페24 공용
나라별 환산표는 버린다. 크리마 핏 위젯이 있는 상품은 `crema_fit` 이 찍혀 `fetch_cremafit.py --auto` 가 알아서 묻는다.
세트(`set_option_data`)는 구성품 단품의 표를 상의 + 하의(`_parts`)로 붙인다.

자동으로 읽은 값은 라벨 범위(`size_labels.json`)를 벗어나면 뺀다. 둘레로 적힌 값은 반으로 나눠 단면으로
맞추고, 둘레인지 단면인지 가릴 수 없으면 비운다(**틀린 값보다 빈 값**).
수기(`manual_sizes.csv`)는 사람이 판단한 값을 그대로 적용한다. 수치 변환·반올림, 행 자르기·합치기·정렬,
이름 추정을 하지 않는다. 세트의 하의 표도 같다. 기계 표의 **빠진 축만** 붙이되(겹치는 칸이 1cm 안에서 같을 때),
화장이 있으면 어깨·소매길이, 하의 표가 따로 있으면 하의 축, 빈 칸이 섞인 축은 붙이지 않는다.
수기 오류·누락은 원본 CSV에서 고친다. 형제 상품에는 독립된 복사본을 주어 형제의 후처리가 수기를 바꾸지 않게 한다.

매장마다 어느 칸에서 얻었는지는 데이터 저장소 `data/reports/brand_collection.md`(`brand_collection_report.py` 가 만든다 — 비공개라 여기 두지 않는다).

**설명·소재** — 같은 결: HTML 글이 있으면 그것으로 끝, 없으면 그림에서 읽은 글(`detail_from_ocr.py`)에서
소재·취급·설명 문장만 골라 뽑는다(사람 지시 2026-09-05 「html에 있으면 그걸로 끝. 없으면 이미지」).
앱에 나가는 설명은 `product_desc.py` 가 씻는다(배송·교환 공지 · 주문 상자 · 틀 조각 · 반복 문구 · 탭 · 단추 글자).
매장 단위로 보는 것은 `export_app_data.build_descs` 가 한다 — 매장 설명 20%(20편) 넘게 · 두 갈래 넘게 되풀이되는
문장(상용구), 옷과 잡화에 다 붙은 남의 혼용률 틀, 같은 매장 다른 상품의 이름 · 값 목록(2026-10-27).
앱에 보이는 이름(`n`)은 `export_app_data.display_name` 이 판촉 · 배송 · 차수 · 색 개수 · 셀럽 Pick · 품번을 떼어 만든다 —
상품표의 `name` 은 그대로 둔다(색 형제 묶기 · 갈래 · 태그가 원래 이름을 읽는다).

**채우기 한 바퀴** — `fill-gaps`(`fill.yml`): ① 상세 다시 열기(`refetch`, select=gaps) → ② 그림 읽기(`ocr`).
①에서 채워진 상품은 ②에서 저절로 빠진다. 자동 일정은 꺼 두고 필요할 때 손으로 띄운다(사람 2026-09-26).

**막히면 코덱스에게** — 위 차례로도 사이즈표가 안 나오는 매장(그림 글자가 흐려 OCR 이 못 읽음 · 표가 어디 숨었는지
모름 · 틀이 낯섦)은 혼자 붙잡지 않는다. PR #14 로 코덱스에게 묻고, 필요하면 코덱스가 **그림을 직접 보고(비전)**
표를 읽게 한다(사람 결정 2026-09-28). 둘이 방안을 주고받아 더 나은 길을 찾으면 그 길을 수집기에 넣고 여기 차례에 적는다.
사진은 그때도 저장소에 올리지 않는다 — 주소만 주고 코덱스가 연다.

## 3. 생성물 다시 만들기 (이 차례를 지킨다)

`detail_from_ocr.py` → `crawl_cafe24.py --build-csv` → `size_from_ocr.py` → `tag_items.py`

- `size_from_ocr` 는 `products_full.csv` 를 읽으므로 **build-csv 가 먼저**다(순서를 틀려 한 번 헛돌았다, 2026-09-07).
- 생성물(`products_full.csv` · `product_sizes.json` · `product_tags_full.json`)은 원본의 함수라 CI 가 만든다.
  로컬에서 만들어 밀지 않는다.
- 상품 태그는 `tag_items.py` 의 13축이다(`function` 기능 축이 2026-09-05 추가됨).
- **사진 무늬 · 색** — `photo_attrs.py` 가 사진 임베딩(옷만 자른 판 우선)에 글 프롬프트를 대어 `photo_attrs.json` 을 만든다
  (워크플로 `embed`, 임베딩 다음 · 비슷한 옷 전). 앱 `pt`(무늬 있음)와 비슷한 옷의 무늬 묶기는 `photo_attrs.pattern_keys`
  하나가 정한다 — 이름 무늬 낱말 > 사진(눈으로 잰 문턱) > 본문 태그. 앱 `co` 는 옷에 한해 사진이 확신할 때만 고치거나
  빈 것을 채운다(`photo_attrs.color_photo`). 문턱의 근거는 그 파일 주석(사진 선별기 360벌 눈 검증, 2026-10-27).
- 착용컷 표시(wn)는 옷 분할 넓이(`worn_photo.py` → `data/worn_photo/`)와 글-사진 착용 점수(`worn_zs.py` → `data/worn_zs.json`,
  사진 임베딩 `embed_photos.py --model siglip` 다음에 `embed` 워크플로에서 돈다)를 `export_app_data.worn` 이 합친다(2026-10-27). 임베딩을 다시 만들면 점수도 다시 낸다.
  새 임베딩은 사진 주소도 남겨 점수와 대표 사진을 대조한다. 사진 주소 없는 구판은 변경 확인에 한계가 있어 분할 결과에서 사진 변경이 확인되면 쓰지 않는다(2026-10-28).
- `rebuild` 는 `photo_fill_metrics.json` 과 `size_stats.json` 도 데이터 저장소에 커밋한다.
  둘 다 `generated_at` 은 UTC 실행 시각이고, 비율은 0~1이다. 사진 통계는 브랜드 10% 검증의
  축별 `accuracy` · `sample_count` · `high_confidence_fraction` · `high_confidence_accuracy` ·
  `high_confidence_count` 를 기록한다(확신 기준 `confidence_threshold=0.8`). 디테일은 값마다 따로 적고,
  확신 구간은 기존 화면 출력처럼 양성 예측만 센다. 표본이 없는 정확도·비율은 `null` 이며,
  학습할 갈래 부족·검증 브랜드 부족·임베딩 없음은 `status` 로 구별한다. `--dry-run` 은 저장하지 않는다.
  사이즈 통계의 `total_products` · `products_with_sizes` 는 마지막 화면의 전체/사이즈 있는 상품 수이고,
  `size_keys` 는 화면에 찍는 매칭 상태별 상품 수, `size_keys_products` 는 그 합이다(키 문자열 수가 아님).

## 5. 검증 — 앱에 내보내기 전

1. **1차 전처리(Claude)** — 수집 뒤 칸별 채움률을 매장마다 세고, 이상한 값을 먼저 걸러 고친다.
2. **전처리 검증(Codex)** — 매장마다 몇 벌씩 표본을 뽑아(상품 링크만, **사진은 올리지 않는다**)
   layer-web PR #14(중계 전용 · 병합 금지) 댓글에서 코덱스에게 맡긴다. 코덱스는 페이지와 우리 값을
   칸마다 대 보고 **같은 꼴로 되풀이되는 틀림**을 짚는다. 결과는 댓글로 받는다.
   국내 IP 가 필요한 일(국외 차단 매장)만 사람 PC 의 코덱스 중계(`relay/inbox/`)로 보낸다.
3. **가르기(Claude)** — 짚은 것을 「버그」와 「설계」로 가른다. 버그는 고치고 **고치기 전후를 전 매장에
   대 본다**(바뀐 수 · 줄어든 것 표본). 설계와 판단이 필요한 것만 사람에게 묻는다.
4. **앱 공개(사람)** — `NEW_HOLD` 에서 빼는 것은 사람이 수치를 보고 정한다.

## 6. 늘 지키는 것

- 매장 서버에 호스트당 1초 안팎. robots.txt 가 막은 길(예: 재고 API)은 부르지 않는다.
- 무신사는 자동 수집하지 않는다(약관).
- 할인가: 카페24 는 지금 정가만 쓴다(사람 결정 2026-09-28 — 나중에 「할인가 + 정가 + 확인 날짜」로 바꾼다).
- 품절 상품의 할인(줄 그은 정가 `op`)은 매장 페이지가 아직 보여 주면 그대로 낸다. 목록에서 내려간 상품(delisted)은
  확인할 페이지가 없어 `op` 를 안 낸다. 값 `p=0` 은 「값 모름」(매장이 값을 내린 품절)이다(2026-10-27).
- 사진은 저장하지 않는다 — 주소만 둔다.
